# Release checklist (plan/features/0015 F3, ADR-0125, ADR-0119, ADR-0120)

A release is the exact output of `.github/workflows/release.yml` for a `v2.X.Y[-pre]` tag: it builds, signs,
checksums and attests the packages and creates a **draft** GitHub release. A maintainer reviews and publishes
it. Nothing in this repository creates tags or publishes releases by itself.

## One-time repository setup (maintainer, repository settings)

- [ ] Environment `release` with required reviewers; the secrets of [README.md](README.md#secrets-environment-release-required-reviewers) only there.
- [ ] Tag protection (repository rule): only maintainers may create tags matching `v2.*`.
- [ ] Azure Trusted Signing: HARDWARIO a.s. identity validation done (can take weeks; fallback: a cloud-HSM OV
      certificate through a new ADR, ADR-0120), certificate profile created, federated credential for
      `repo:hardwario/hio-monitor:environment:release`.
- [ ] Apple: Developer ID Application certificate and an App Store Connect API key (role Developer) for notarytool.

## Release gates (all must hold before tagging)

- [ ] **Legal sign-off of the LGPL exception (ADR-0119):** the amended `LICENSE` (HARDWARIO licence + LGPLv3 §4
      exception, wording approved by HARDWARIO's legal counsel) is committed. No release without it.
- [ ] **Legal review of `Qt-SOURCE.txt`** (the written offer for the Qt sources, generated by
      `packaging/common/licenses.cmake`): wording and the contact are approved.
- [ ] **.deb maintainer e-mail:** `CPACK_DEBIAN_PACKAGE_MAINTAINER` in `packaging/linux/deb/cpack-deb.cmake` is
      still the placeholder `support-email-pending@hardwario.invalid` — HARDWARIO supplies the support address.
- [ ] `check_translations`: 0 unfinished Czech entries (ADR-0027; the gate job fails otherwise).
- [ ] CI is green on the commit to be tagged (`v2-dev` or the release branch), including the three
      `package-<os>` jobs.
- [ ] Manual verification matrix of plan 0015 (F4) on the release candidate: Ubuntu 22.04 AppImage, Ubuntu
      24.04 / Debian 13 .deb, Fedora AppImage, macOS 13 Intel and macOS 15 Apple silicon DMG, Windows 10 22H2 and
      Windows 11 MSI (install, upgrade, downgrade refusal, uninstall, silent install, SmartScreen, J-Link with
      Defender), the crash notice after `HIO_TEST_CRASH=1` (debug build). Results are recorded in plan 0015.
- [ ] Release notes draft: minimum OS versions, "Install SEGGER J-Link Software 8.00 or newer separately", the
      side-by-side period with v1 (until M8).

## Tagging and publishing

1. Tag the commit: `git tag -s v2.X.Y -m "HARDWARIO Monitor 2.X.Y"` (pre-releases: `v2.X.Y-rc.N`), push the tag.
2. `release.yml` runs: gate → tests (ci.yml) → linux / macos / windows (environment `release`: approve the
   deployment) → publish (draft release with all assets, `SHA256SUMS`, attestations).
3. Review the draft: assets (`hio-monitor-<v>-x86_64.AppImage`, `hardwario-monitor_<v>_amd64.deb`,
   `hio-monitor-<v>-macos-universal.dmg`, `hio-monitor-<v>-windows-x64.msi`, `SHA256SUMS`,
   `hio-monitor-<v>-symbols-{linux,macos,windows}.zip`), the generated notes, the pre-release flag
   (set automatically for tags with a `-`).
4. Spot checks: `sha256sum -c SHA256SUMS`; `gh attestation verify <file> --repo hardwario/hio-monitor`;
   macOS `spctl -a -t open --context context:primary-signature -v <dmg>`; Windows `signtool verify /pa <msi>`.
5. Publish the release. The update check (plan 0016) announces it to users within 24 h (v2 releases only;
   pre-releases only to users who opted in).

## After the release

- Keep the symbol archives with the release (crash dumps are symbolized with them, ADR-0123).
- If a release must be withdrawn: unpublish it (back to draft) on GitHub; never delete or move a tag.
