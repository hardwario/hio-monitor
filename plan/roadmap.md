# Roadmap

Each milestone is broken into feature plans in `features/`. A milestone starts only after its
plans are Approved. Every milestone also delivers the CLI commands for its features
(see [0006-cli.md](0006-cli.md)).

| Milestone | Content | Status |
|---|---|---|
| **M0 — Skeleton** | CMake + presets, toolchains, CPM, CI on 3 OSes, sanitizers, clang-tidy/format; `libs/core`: `hio::Error`, `Result`, logging, settings, bounded buffers; empty GUI app; CLI skeleton (CLI11, `--version`, `--json`, error/exit-code rendering); translation infrastructure EN + CS (ADR-0027) | In progress — [features/0001](features/0001-m0-skeleton.md) |
| **M1 — J-Link & RTT** | runtime loading of JLinkARM (per-session copies), probe discovery, `DeviceSession`, RTT transport (find by name, reconnect, reset/power-loss detection), CHESTER profile; CLI `chester app console` / `command`, `jlink list` / `info` / `update-firmware` | In progress — [features/0002](features/0002-m1-jlink-rtt.md) (phases A–F implemented on `v2/m1-jlink-rtt`, verified with the fake J-Link library; Done after the hardware tests G1/G2) |
| **M2 — Flashing** | hardware spike (ADR-0015), `IProgrammer` on J-Link (ADR-0035), program/erase/reset/recover workflows (app + LTE), UICR rules (ADR-0036), nRF Util modem update (ADR-0016, 0040, 0042), firmware download by ID + bounded cache (ADR-0037); CLI `chester app/lte flash/erase/reset/recover`, `pib/uicr read` | In progress — [features/0003](features/0003-m2-flashing.md) (approved 2026-10-11 with ADR-0057/0062; implemented on `v2/m2-flashing`; Phase 0 spike and HIL with the CHESTER after A–F) |
| **M3 — GUI core** | device tabs, navigation, console page (shell + log), search/filter/history/batch, flash page, settings (incl. language), themes; design system + mockups in [gui/](gui/design-system.md) | In progress — [0004 shell](features/0004-m3-gui-shell.md) (approved 2026-10-12, on `v2/m3-gui`), [0005 console](features/0005-m3-console.md) and [0006 flash + settings](features/0006-m3-flash-settings.md) Draft (0005 ∥ 0006 after 0004, ADR-0059; 0006 after M2) |
| **M4 — Wizards & error UX** | wizard framework, `libs/diag` (`hio doctor`, `hio diag report`, `hio chester app\|lte check`, `Diagnose` operation), first-run setup, connect device, troubleshooting, flash wizard, diagnostic report | Approved 2026-10-16 (on `v2/m4-wizards`; 0007 first) — [0007 framework](features/0007-m4-wizard-framework-diagnostics.md), [0008 setup](features/0008-m4-first-run-setup.md), [0009 connect + troubleshooting](features/0009-m4-connect-and-troubleshooting.md), [0010 flash](features/0010-m4-flash-wizard.md) (0008 ∥ 0009 ∥ 0010 after 0007, ADR-0065) |
| **M5 — Bluetooth LE** | NUS transport, scan/connect UI, pairing help (BlePairing wizard, macOS Bluetooth permission step), CLI `ble scan` / `ble console` / `ble command` / `ble pair` | In progress — [0011 backend + CLI](features/0011-m5-ble-backend-cli.md) implemented on `v2/m5-ble` (HIL and manual checks pending), [0012 GUI + pairing](features/0012-m5-ble-gui-pairing.md) next (ADR-0078) |
| **M6 — MCP** | `libs/mcp` (own JSON-RPC/MCP core for 2025-11-25 + 2026-07-28, stdio + HTTP transports), rttt-parity tool set + flash/erase/recover/diagnose, new low-level target operations, CLI `hio mcp [--http]` and target commands; GUI server on 127.0.0.1:47800 with token, consent dialogs, console markers, activity list | In progress — [0013 core + tools + CLI](features/0013-m6-mcp-core-cli.md) approved 2026-10-20 (phases A–C being implemented on a branch from `v2/m5-ble`), [0014 GUI](features/0014-m6-mcp-gui.md) Draft (after 0013, ADR-0094) |
| **M7 — Packaging & release** | AppImage, Flatpak, .deb, DMG, Windows installer, signing, update check | Not planned |
| **M8 — Parity & retirement** | parity checklist in 0002 complete, beta with users, old app retired | Not planned |
